# Contributing to Zolna

Thank you for helping develop learning resources for Sudanese children in the USA. The project is in its planning stage; proposed work should be labeled clearly.

## Suggest an improvement

Open an issue describing the learner need or problem, intended age group and Arabic level where relevant, and a specific suggested change. For technical bugs, include reproduction steps, expected behavior, and observed behavior using fictional data.

## Submit a change

1. Discuss substantial curriculum or technical changes in an issue.
2. Make a focused pull request explaining what changed and why.
3. Identify sources, permissions, and any use of AI assistance.
4. Describe review or testing performed and remaining limitations.

The maintainer reviews changes before merging. Contributors should discuss licensing before substantial contributions while a project license is being selected.

## Organize original documents

Use descriptive lower-case English filenames with hyphens where practical; preserve Arabic titles inside each document. Keep Zolna as the current project name, retaining historical names only when they explain provenance.

| Material | Destination | Example |
| --- | --- | --- |
| Feasibility study | `docs/planning/` | `zolna-feasibility-study-ar.md` |
| Development plan | `docs/planning/` | `zolna-development-plan.md` |
| Strategic review | `docs/planning/` | `zolna-strategic-review.md` |
| Resource guide | `research/` | `arabic-learning-resources.md` |
| Reviewed lesson | `curriculum/` | `lesson-01-greetings-ar.md` |
| Website demonstration | `prototypes/` | `zolna-website.html` |

These are naming examples, not claims that these files have been imported.

Before importing, compare file contents rather than filenames alone. Keep one canonical editable version and useful PDF exports. Preserve materially different drafts with clear version labels. Exclude installers, temporary files, and archives whose contents have not been reviewed. Do not overwrite distinct work just because titles match.

For each document, record its title, author or source, date, version, language, review status, and reuse permissions. Distinguish proposed budgets or forecasts from observed results.

## Curriculum review

Check learning objectives, age suitability, language accuracy, cultural representation, attribution, activity instructions, and a simple assessment. Obtain educator feedback before treating a lesson as validated.

## Prototype review

Document how to run the prototype and which controls work. Check Arabic right-to-left layout, English navigation, mobile screens, keyboard operation, and core lesson interactions. Do not describe mockups as production applications.

## Privacy and respectful participation

Use fictional learner examples. Do not upload children’s personal information, family records, credentials, or private contact details. Represent Sudanese communities respectfully and welcome corrections from people with relevant lived and educational experience. Link to external resources unless permission allows copying.
