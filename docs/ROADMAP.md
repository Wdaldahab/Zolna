# Zolna development roadmap

A proposed sequence, not a record of completed work. Track progress with reviewed files, issues, tests, and releases.

## 1. Recover and organize existing work

- [ ] Import original curriculum, feasibility studies, resource guides, and website prototypes.
- [ ] Compare duplicate copies by content and retain one canonical source plus useful exports.
- [ ] Review personal information, redistribution rights, unsupported claims, and Zolna naming.
- [ ] Place plans in `docs/planning/`, references in `research/`, lessons in `curriculum/`, and demos in `prototypes/`.
- [ ] Record each document’s source, author, date, and review status.

Done when: documents are indexed and readable, with no unrelated installers or unexplained archives.

## 2. Define a small curriculum pilot

- [ ] Choose one age band and starting Arabic level with educator input.
- [ ] Draft measurable objectives and three sample lessons.
- [ ] Include instructions, duration, materials, and a learning check.
- [ ] Obtain educator and family feedback on language, culture, and age suitability.

Done when: pilot lessons are reviewed and unresolved feedback is documented.

## 3. Build a usable website prototype

- [ ] Review existing HTML files and select a maintainable technical approach.
- [ ] Support Arabic right-to-left and English navigation.
- [ ] Build a lesson list, lesson view, and simple progress interaction with fictional data.
- [ ] Check keyboard access, readable contrast, mobile layout, and Arabic text rendering.
- [ ] Document local setup and test core interactions.

Done when: a reproducible demo passes core checks and states its limitations.

## 4. Establish sustainable maintenance

- [ ] Choose licenses for original code and educational content; check third-party permissions.
- [ ] Track bugs and requests through issues with reproducible details.
- [ ] Review changes through pull requests and publish a changelog for meaningful releases.
- [ ] Define a privacy-conscious feedback process before using real learner information.

Done when: licensing, contribution guidance, and release steps are clear.

## 5. Evaluate and improve

- [ ] Run a small voluntary pilot with suitable consent and educator oversight.
- [ ] Collect only information needed to evaluate usability and lesson objectives.
- [ ] Report actual participation, findings, and limitations.
- [ ] Revise from observed learning needs and accessibility feedback.

## Evidence for maintainer or funding applications

Use verifiable repository links, actual functionality, reviewed lessons, releases, and real usage. Separate plans from completed work. Do not invent stars, downloads, users, partnerships, learning outcomes, or maintenance history.
